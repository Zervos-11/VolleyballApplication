# Strict team-metric input and gate

The [calculator](../scripts/compute_honours_team_metrics.py) implements the three prespecified team metrics in [contract alignment](HONOURS_CONTRACT_ALIGNMENT.md): mean pairwise spacing, convex-hull area and centroid dispersion. It accepts one of the [18 frozen primary-match points](HONOURS_RALLY_SAMPLE.md) only after the near-side team, rally boundaries and court calibration have been source-reviewed. The [current side map](../data/processed/honours_near_side_assignment.json) is provisional despite the confirmed UTS side change, so it does not pass this gate. The calculator does not turn tracker boxes or held positions into floor coordinates.

Input is a JSON file with `match_id`, `source_sha256`, `set`, `point_number`, `winner`, `near_team`, `near_team_evidence_status: "source_reviewed"`, `calibration_status: "validated_for_metric_use"`, `start_frame`, `end_frame_exclusive`, `near_player_ids` (six unique string IDs), and `frames`. The interval must have either `rally_boundary_status: "source_reviewed"` for an entire rally or `analysis_window_status: "source_reviewed_fixed_window"` for a prespecified live interior. The output identifies which interval type was used. The current UCLA transition register is navigation evidence only; its interiors have not yet been certified for this fixed-window input. Every supplied frame has its integer `frame` and a `players` object with exactly those six IDs. Each player entry has a `status`, finite court `x_m` and `y_m` in the inclusive 0-9 m court, or null coordinates if unavailable. Set `position_method` for the whole input to either `reviewed_floor_contact` (the default, requiring that status for every eligible player) or `reviewed_grounded_box_bottom_proxy` (requiring that status). The latter means a source-reviewed grounded player's box-bottom centre was projected through a validated court transform; it does **not** require an individual shoe click on every frame. An airborne, clipped, occluded, out-of-frame or otherwise unknown player gets a different explicit status and null coordinates. The calculator rejects mixed methods within one rally and never synthesizes positions to pass the gate.

The source tracking ledger may retain a person's raw ID, image box and image centre while their metric floor coordinates are null. A jump therefore does not end the image track. From the first confirmed airborne frame, exclude the player's floor point until a later source-reviewed grounded contact; leave intervening unreviewed frames unknown. A last-grounded takeoff point carried forward is an imputation scenario and must stay outside this strict observed-position input. The [S1 P6 box-and-floor ledger](HONOURS_U5_S1P6_BOX_AND_FLOOR_LEDGER.md) implements this separation for one fixed window.

These status strings are provenance attestations supplied with the input. The calculator checks their format and computes eligible frames; it cannot determine from a JSON flag whether a human actually reviewed an event, whether a court calibration was independently accepted or whether a player was grounded. The supporting source review must be documented before setting a validated status. The [S3 P34 readiness audit](HONOURS_U5_S3P34_VALIDATION_READINESS.md) records why its current evidence cannot yet carry those attestations.

The output has per-frame null metrics with reasons when any slot is unusable, plus rally medians of the three metrics across eligible frames. It reports submitted and eligible counts, `eligible_fraction_of_submitted_frames`, and `eligible_fraction_of_interval`. The latter divides by every source frame between the reviewed endpoints; for a deliberate 5 Hz sample of a 30 fps video, it is a source-frame density measure and will be about one sixth even if every sampled frame is eligible. State the sampling schedule and both denominators when reporting coverage. It maps the score winner to a near-side win only after the near-side team is verified. The present 0-9 m coordinate gate deliberately restricts this measure to all-six-in-court formations. The [R2 source screen](HONOURS_R2_READINESS.md) shows a player may legitimately move beyond the sideline; if off-court formations become part of the question, revise the definition and independently validate the extrapolated court coordinates first. No significance test or outcome association is produced from one rally.

The input also requires `near_roster_review_status: "source_reviewed_near_six"`, recording a source check that all six named slots belong to the near-side team. The [R2 roster adjudication](HONOURS_R2_READINESS.md) found that saved slot 42 belongs to near-side UTS #22 at its dense anchors while an assisted track assigned to it followed a far-side player for six frames. The calculator rejects unverified rosters.

For the UCLA–Concordia primary match, pass its separate frozen score-only sample explicitly. The default sample remains the earlier ProVolley–UTS development match. The current [dense primary-match result](HONOURS_U5_DENSE_RESULTS_AND_READINESS.md) has zero source-validated eligible frames; provisional six-box snapshots do not meet this input contract.

Run after reviewed input exists:

```powershell
.\.venv\Scripts\python.exe scripts/compute_honours_team_metrics.py --input path\to\reviewed_rally.json --output path\to\team_metrics.json
.\.venv\Scripts\python.exe scripts/compute_honours_team_metrics.py --sample data\matches\yt_u5HnY2aNW14\screening\rally_sample_score_only.json --input path\to\reviewed_u5_rally.json --output path\to\u5_team_metrics.json
```

No frozen-sample rally currently has the required six-player, independently validated court-floor input. This script defines and checks the computation; its existence is **not** evidence that the learning contract's three calculated metrics or outcome comparison have been achieved.

The [proxy disagreement audit](HONOURS_BOX_BOTTOM_DISAGREEMENT.md) compares saved foot markers with box bottoms on the current sample. It measures method sensitivity, not independent error. Before using the box-bottom mode for final metre-valued results, the source review still needs to confirm grounded boxes and near-side membership on the analyzed frames, and the project must state the proxy's measured reference error and acceptable tolerance.
